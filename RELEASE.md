# Выпуск новой версии (инструкция для Claude на компьютере автора)

Пользователям этот файл не нужен. Автор говорит «выпусти обновление» — делай по шагам.

## Один раз: подключить GitHub
1. Аккаунт GitHub и пустой **публичный** репозиторий человек создаёт сам на github.com.
   Пароль и коды от GitHub в чат не просить и не вводить.
2. Вход: `gh auth login --web`. Человек сам подтверждает вход в браузере.
   Если `gh` не установлен — предложи поставить (`brew install gh`) и дождись «да».
3. В `release.json` впиши `"repo": "<логин>/<репо>"`.
4. `git init -b main`, `git remote add origin https://github.com/<логин>/<репо>.git`.

## Каждый выпуск
1. **Версия.** Подними `version` в `release.json` (1.1 → 1.2; крупные изменения → 2.0).
2. **CHANGELOG.md.** Сверху новая запись: дата, строка «Установщик: нужен / не нужен»
   («нужен», только если менялись `setup/` или требования к программам и моделям)
   и список изменений человеческим языком.
3. **Проверка, что не утечёт личное.** Обязательно перед каждым push:
   - `git status --short`: в списке не должно быть видео, `projects/`, `kit.json`, `bin/`, `models/`, `cache/`;
   - `git grep -nE "/Users/|C:\\\\Users\\\\|@gmail|@mail|api[_-]?key|token|sk-[A-Za-z0-9]"`:
     найденное покажи автору, личное убери;
   - файлы крупнее 5 МБ (`git ls-files -s | ...` или `du`) — покажи и спроси.
4. **Проверка набора.** `python tools/preflight.py --full` → `OK`. Если менялись скрипты в `tools/`,
   прогони их на `projects/HHH` или другом готовом проекте.
5. **Покажи автору** список изменённых файлов и запись из CHANGELOG. Дождись «да».
6. **Публикация:**
   ```bash
   git add -A
   git commit -m "Версия <X.Y>"
   git tag v<X.Y>
   git push origin main --tags
   ```
7. Через минуту проверь, что `https://raw.githubusercontent.com/<repo>/main/release.json`
   отдаёт новую версию. С этого момента пользователи в течение суток увидят подсказку
   в preflight.
